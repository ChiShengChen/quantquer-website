# Benchmark 方法與結果

公開表格、條件與原始紀錄在 [工程 Benchmark](/labs/benchmarks/)；重跑說明與 JSON schema 在 [資料目錄](../benchmarks/README.md)。

| 實驗 | 現有結果 | 適用範圍 |
| --- | --- | --- |
| 影像修補 | 室內 MI-GAN 529.850 ms p50、572.856 ms p95、23.37 dB；Telea 6.600 ms、6.744 ms、22.75 dB | Intel i9-12900KS，ONNX Runtime CPU，兩組已知背景及合成遮罩，暖機 5 次、每條件 30 次 |
| 影像修補戶外例 | MI-GAN 524.292 ms p50、649.692 ms p95、13.19 dB；Telea 6.150 ms、6.354 ms、14.04 dB | 遮罩內 PSNR 依場景而異。CPU 重跑的 10 個輸出 WebP 逐位元組一致，4 組 PSNR 一致，延遲保留原始快照 |
| GPU 排程 | 两個 GPU 任務依序執行，CPU 任務與 GPU A 重疊，兩個 GPU 程序的 VRAM 取樣峰值均 286 MiB | 一個 24 GiB GPU、2 個工作槽。單機受控紀錄與合成政策比較分別標示 |
| 光子網格 | 四通道、四階段 MZI，預設模擬 7.87% 總功率損失、22.38% 相對輸出差 | 理想複數光場的數值結果。無實體晶片量測 |
| 引文稽核 | 公開固定版本重跑 4 組合成比對 | 引文與數字規則，沒有語意正確率或 LLM 效能結果 |

新測試至少保留資料來源、授權、工具版本、硬體、OS、精度、輸入、暖機及取樣次數、統計方法和限制。可能暴露客戶或使用者內容的紀錄經匿名與公開審核後發布。

目標 NPU、端到端影片、多卡、多工作負載硬體 A/B、長時 GPU 吞吐和實體光子故障缺實測資料。選定量產裝置後再用相同驗收條件和機型專屬記錄增加基準。

目標硬體取得實機執行資料後，可用 `node benchmarks/scripts/vision-npu.mjs --help` 驗證執行位置、雜湊、延遲樣本與裝置資訊。輸出供人工證據審查，加入公開索引須另行核對。GPU 五種政策的模型與固定合成工作集附於 [GPU 排程比較](/labs/evidence/gpu/#policy-simulation)。
